# BCM-01 — Executive summary

**Question.** With every trajectory and outcome held fixed, how sensitive are the Behavioral
Consistency Metric (BCM) scores and system rankings of Raichura & Banerjee (arXiv:2608.13598)
to data construction, folds, predictor, explainer and comparison population?

**Scope.** This is a measurement-validity audit on 9,191 public trajectories. No new agent runs
and no LLM calls. It says nothing about whether agents make task-appropriate decisions.

## Main findings

1. **The data path has a silent bug that favours the proprietary systems.** 2,513 of 4,000
   SWE-smith trajectories (Claude-3.5 54%, Claude-3.7 68%, GPT-4o 14%) parse to zero steps,
   because the loader filters on `message_type`, which plain-format records lack. In every fold
   these rows share one SHAP vector. Excluding them from the comparison population drops
   Claude-3.7 from 0.759 to 0.511 (shipped: 0.766 → 0.514).
2. **The two sources are measured with different instruments.** For proprietary systems a "step"
   is the assistant's thought text. For Llama systems it is every message, including the ≈5k-char
   system prompt, the issue text and all environment observations, which the regexes label
   edit/view 100% of the time. Parser, data source, scaffold, task set and model family coincide.
3. **The headline ordering is robust to the core perturbations, but magnitudes are not.**
   Across 11 fold seeds, 9 competent LightGBM variants and task-grouped CV, no proprietary-vs-Llama
   pair ever reverses (separation 0.43–0.60). GPT-4o moves by up to 0.12 [0.09, 0.16].
   Within-Llama order flips (Llama-405B vs Llama-8B in 29% of bootstrap replicates).
4. **The separation does not survive changes that matter for construct validity.**
   - Role-aware parsing at fixed trajectories: separation 0.487 [0.394, 0.564] → 0.122
     [0.058, 0.205]; Claude-3.5 0.785 → 0.435.
   - Exploratory logistic predictor with AUC inside the pre-specified ±0.03 window: separation
     −0.008 [−0.058, 0.051].
   - Interventional TreeSHAP raises Llama BCMs by 38–78% (ordering kept).
5. **Negative controls: high proprietary BCM does not require outcome signal.** Permuting labels
   within each system (no trajectory–outcome link) leaves Claude BCMs in the same range
   (0.69–0.85 vs real 0.76–0.79). For every Llama system, and for every system under role-aware
   parsing, the *real* BCM is lower than all 10 within-system null BCMs. The success predictor is
   at chance *within* each proprietary system (within-system AUC 0.47–0.56) but informative
   within Llama (0.71–0.88). Mechanistically, high BCM here reflects one dominant, uniformly
   signed attribution (step count or prompt length, which proxy the data source), not a stable
   success-relevant strategy.
6. **Within- vs between-task.** Within-task > between-task holds for all Llama systems (+0.22 to
   +0.26; role-aware +0.13 to +0.18) on identical eligible cohorts, and task-balancing barely
   changes global values. This replicates descriptively. Same-task pairs share issue, repository
   and difficulty, so the gap does not by itself establish "global fragmentation".

## Supported conclusions

- **Supported:** On this cohort, BCM rankings between the two *data sources* are stable under fold,
  tree-hyperparameter and task-grouping perturbations. Same-task attribution vectors are more
  similar than cross-task ones for the Llama systems.
- **Not supported:** that the proprietary-vs-open gap reflects behavioural consistency of the
  models. It is confounded with source, scaffold, task set and an asymmetric parser. It shrinks 4×
  with a corrected parser, vanishes under a competent linear predictor, and its proprietary
  values are reproduced by label-permuted models. Also not supported: that the published
  magnitudes (e.g. GPT-4o 0.814) are regenerable from the released code.
- BCM magnitude is not interpretable without the within-system null and the within-system AUC.

## Recommended next experiment

Phase 2, as planned in the brief: a **source-controlled, decision-ground-truth study**. Run
proprietary and open models under *one* scaffold and *one* trajectory format on *one* task set,
with ≥5 repeats per task and controlled task variants. Parse with the role-aware parser, and
report every BCM next to its within-system label-permutation null and within-system AUC. Before
that, ask the authors for the environment and intermediate files behind
`results/files/oof_shap_matrix.npy`.
